# ربط الحضور والانصراف بجوجل شيت

1. أنشئ ملف جوجل شيت جديد باسم «حضور جادو» (من نفس حساب جوجل الخاص بـ Firebase).
2. من القائمة: **الإضافات ← Apps Script**.
3. احذف الكود الموجود في `Code.gs` والصق محتوى `all.gs` كاملًا (يجمع core.gs و server.gs):
   https://raw.githubusercontent.com/companyjadu-sketch/JADU-APP/main/apps-script/all.gs
4. اختر الدالة `setup` واضغط **تشغيل** مرة واحدة، ووافق على الصلاحيات.
   تُنشأ الأوراق: الموظفون، القواعد، سجل التعديلات، ومشغّل يومي يسجّل الغياب الساعة 9 مساءً.
5. **نشر ← نشر جديد ← تطبيق ويب**: التنفيذ باسم «أنا»، والوصول «أي شخص». انسخ الرابط المنتهي بـ `/exec`.
6. ضع الرابط في `attendance.js` بالمتغير `ATT_API_URL`، ورابط الشيت في `ATT_SHEET_URL`.

الموظفون يختارون أسماءهم مرة واحدة على هواتفهم. إضافة موظف أو إيقافه من صفحة الإدارة.

# رفع صور الأصناف (photos.gs)

الكود في `photos.gs` ويُجمَّع داخل `all.gs`. **لا تعدّل `all.gs` يدويًا** — عدّل الملفات المصدرية ثم شغّل:

```
node apps-script/build-all.js
```

(النشر التلقائي عبر GitHub Actions يرفع `all.gs` كما هو عند أي تعديل عليه في main.)

## من يستطيع الرفع؟ (التحقق يتم في الخادم)

| الهوية | الشرط | ما يحدث لصورته |
|---|---|---|
| إدارة عامة | توكن Firebase صالح + إيميل ضمن `ADMIN_EMAILS` | تُنشر مباشرة إلى `images/رقم-الصنف.jpg` |
| موظف | هاتف «معتمد» في ورقة **الأجهزة** والموظف غير موقوف في ورقة **الموظفون** | تذهب لمجلد انتظار في Drive وتنتظر موافقة الإدارة |
| أي هاتف آخر | — | مرفوض (خطأ نهائي) |

القائمة تُقرأ من الشيت في كل طلب، فأي موظف يُسجَّل لاحقًا يعمل تلقائيًا دون تعديل كود.

## الإعداد لمرة واحدة (حساب جادو)

1. **مفتاح GitHub**: في GitHub ← Settings ← Developer settings ← *Fine-grained tokens* ← أنشئ مفتاحًا
   لمستودع `JADU-APP` **وحده**، بصلاحية **Contents: Read and write** فقط، وبتاريخ انتهاء.
2. في Apps Script: **إعدادات المشروع ← خصائص النص (Script Properties)** أضف:
   - `GITHUB_TOKEN` = المفتاح (هنا فقط — لا يُكتب في أي ملف ولا يصل للموقع).
   - اختياري: `GITHUB_REPO` (الافتراضي `companyjadu-sketch/JADU-APP`) و `GITHUB_BRANCH` (الافتراضي `main`).
3. شغّل الدالة `photosSetup` مرة واحدة من المحرر ووافق على الصلاحيات (Drive + الاتصال الخارجي).
   تُنشئ ورقة «صور الأصناف» ومجلد «جادو — صور بانتظار الموافقة» في Drive.
4. إن كان ملف `appsscript.json` يحدد `oauthScopes` صراحةً فأضف إليه
   `https://www.googleapis.com/auth/drive` و `https://www.googleapis.com/auth/script.external_request`.
5. بعد نشر الإصدار الجديد جرّب من الموقع بحساب إدارة ثم بحساب موظف.

## ما يكتبه النشر المباشر في المستودع

**كل الدفعة في commit واحد** عبر Git Data API (blobs ← tree ← commit ← تحديث الفرع)، فيُعاد بناء GitHub Pages مرة واحدة:
- الإدارة: الصور تُرفع واحدة واحدة إلى Drive (حالة «جاهزة للنشر») ثم يستدعي الموقع `img_publish` في آخر الدفعة.
  لو أُغلقت الصفحة قبل ذلك يُستأنف النشر تلقائيًا عند فتحها من جديد (والاستدعاء آمن للتكرار).
- الموافقات: «قبول الكل» يستدعي `img_decide_batch` = commit واحد. قبول صورة منفردة = commit لتلك الصورة.
- الحد 100 صورة في الـ commit الواحد؛ ما زاد يُقسَّم على commits بحجم 100.

لكل صورة: ملف `images/رقم.jpg` وسطر في `ITEM_IMAGES` داخل `item-images.js` (برقم إصدار `?v=` ليتجاوز كاش المتصفح).
أي صنف سابق يُستبدل سطره في مكانه، ولا تُمس `MODEL_IMAGES` ولا `TYPE_CODE_IMAGES`.
الصورة تظهر للجميع بعد أن ينشر GitHub Pages التحديث (دقيقة تقريبًا).

سجل كل عملية في ورقة «صور الأصناف» (من رفع، متى، حالة الصورة، ومن قرر).
